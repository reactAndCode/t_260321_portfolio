# 배포 가이드

## 1. 문서 목적
- 본 문서는 `keyword_analysis` 프로젝트를 로컬, 테스트, 운영 환경에 배포하기 위한 절차를 설명한다.
- 현재 프로젝트는 `Next.js 15` 기반의 풀스택 애플리케이션이며, 서버 API와 프론트엔드가 하나의 프로젝트에 포함되어 있다.

## 2. 배포 대상 개요
- 프론트엔드 화면
- 서버 API 엔드포인트 `/api/analyze`
- 외부 연동 API
  - NAVER SearchAd API
  - NAVER DataLab API

## 3. 사전 준비

### 3.1 필수 요구사항
- Node.js 설치
- npm 사용 가능 환경
- 네이버 API 키 준비
  - `NAVER_SEARCHAD_ACCESS_KEY`
  - `NAVER_SEARCHAD_SECRET_KEY`
  - `NAVER_SEARCHAD_CUSTOMER_ID`
  - `NAVER_DATALAB_CLIENT_ID`
  - `NAVER_DATALAB_CLIENT_SECRET`

### 3.2 소스 준비
프로젝트 루트:

```text
D:\dev\vibe_coding\codex_연습\a_02_codex_cli\keyword_analysis
```

## 4. 로컬 개발 환경 배포

### 4.1 의존성 설치

```powershell
npm install
```

### 4.2 환경변수 설정
프로젝트 루트에 `.env.local` 파일을 생성하고 아래 값을 설정한다.

```env
NAVER_SEARCHAD_ACCESS_KEY=발급받은_access_license
NAVER_SEARCHAD_SECRET_KEY=발급받은_secret_key
NAVER_SEARCHAD_CUSTOMER_ID=검색광고_customer_id

NAVER_DATALAB_CLIENT_ID=발급받은_client_id
NAVER_DATALAB_CLIENT_SECRET=발급받은_client_secret
```

### 4.3 개발 서버 실행

```powershell
npm run dev
```

접속 주소:

```text
http://localhost:3000
```

### 4.4 동작 확인
- 첫 화면 진입 시 예시 키워드가 자동 분석되는지 확인
- 검색창에 다른 키워드를 입력하고 결과가 갱신되는지 확인
- 대시보드 상단 우측 모드 표시를 확인한다.
  - `Live Naver Data`
  - `Mock Preview`

## 6. 프로덕션 배포 방식

### 6.1 권장 방식
- Vercel
- 자체 Node.js 서버
- 사내 Linux/Windows 서버

현재 프로젝트는 Next.js 표준 구조이므로 Vercel 또는 Node.js 실행 환경에 바로 배포 가능하다.

## 7. Vercel 배포 가이드

### 7.1 적합한 이유
- Next.js와 기본 호환성이 높다.
- 환경변수 관리가 쉽다.
- 서버 API와 프론트엔드를 함께 운영하기 쉽다.

### 7.2 배포 절차
1. Git 저장소를 준비한다.
2. Vercel에 로그인한다.
3. `New Project`를 선택한다.
4. 저장소를 연결한다.
5. Framework Preset이 `Next.js`인지 확인한다.
6. Environment Variables에 네이버 API 키를 등록한다.
7. Deploy를 실행한다.

### 7.3 Vercel 환경변수 등록 항목

```env
NAVER_SEARCHAD_ACCESS_KEY
NAVER_SEARCHAD_SECRET_KEY
NAVER_SEARCHAD_CUSTOMER_ID
NAVER_DATALAB_CLIENT_ID
NAVER_DATALAB_CLIENT_SECRET
```

### 7.4 배포 후 점검
- 메인 페이지 정상 노출 여부
- `/api/analyze` 응답 여부
- 실데이터 연동 여부
- 에러 로그 존재 여부

### 9.1 로컬
- `.env.local` 사용

- 배포 플랫폼의 Secret/Environment Variable 기능 사용

- 브라우저에 키가 노출되지 않도록 서버 측에서만 사용

## 10. 현재 프로젝트의 배포 관련 동작 방식

### 10.1 데이터 조회 흐름
1. 브라우저가 `/api/analyze?keyword=...` 호출
2. 서버가 네이버 API를 호출
3. 결과를 정규화하여 브라우저에 반환

### 10.2 캐시 정책
- API 응답은 `Cache-Control: s-maxage=3600, stale-while-revalidate=86400` 헤더를 사용한다.
- 동일 키워드 요청에 대해 캐시 활용이 가능하다.

### 10.3 fallback 동작
- SearchAd, DataLab 키가 모두 없으면 mock 데이터 모드로 동작
- 일부 키만 있으면 가능한 API만 사용

## 11. 운영 점검 체크리스트

### 11.1 기능 점검
- 검색창 입력 및 조회 동작
- 검색량 카드 렌더링
- 추이 차트 렌더링
- 연관 키워드 표 렌더링
- 오류 패널 동작

### 11.2 실데이터 점검
- SearchAd 검색량 정상 반영 여부
- DataLab 추이 정상 반영 여부
- 특정 키워드에서 빈 데이터 처리 정상 여부

### 11.3 UI 점검
- 데스크톱 해상도 정상 표시
- 모바일 해상도 반응형 정상 표시
- 긴 키워드 입력 시 레이아웃 깨짐 여부

## 12. 장애 대응 가이드

### 12.1 빌드 실패
- `npm install` 재실행
- Node.js 버전 점검
- 환경변수 이름 오타 점검
- 패키지 잠금파일 이상 여부 확인

### 12.2 API 오류
- 네이버 키 값 재확인
- API 사용 신청 여부 재확인
- 배포 환경변수 적용 여부 확인
- 서버 로그에서 응답 상태코드 확인

### 12.3 화면은 뜨는데 데이터가 없는 경우
- mock 모드인지 확인
- DataLab 또는 SearchAd 중 일부만 설정된 상태인지 확인
- 네이버 API 호출 제한 여부 확인

## 13. 권장 운영 전략
- 1차 운영은 mock 모드가 아닌 실데이터 모드로 검증 후 공개
- 운영 전 대표 키워드 5~10개로 수동 확인
- 장애 대응을 위해 API 오류 로그를 남기는 구조로 확장 권장
- 이후 단계에서 DB 저장, 분석 히스토리, 사용자별 결과 저장 기능 추가 가능
