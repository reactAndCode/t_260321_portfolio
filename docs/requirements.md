# Funding Fee Dashboard 요구사항

## 문서 목적

이 문서는 Funding Fee Dashboard의 요구사항을 날짜별로 관리하기 위한 기준 문서다.
초기 요구사항은 기준선으로 유지하고, 이후 변경 요청은 날짜 단위로 누적 기록한다.

## 요구사항 관리 규칙

- 최초 범위와 공통 원칙은 `기준 요구사항`에 유지한다.
- 추가 요청이나 변경 요청은 `날짜별 요구사항 변경 이력`에 날짜 기준으로 기록한다.
- 각 날짜 항목에는 `상태`를 함께 기록한다.
- 상태 값은 `[대기]`, `[작업중]`, `[완료]`, `[보류]` 중 하나를 사용한다.
- 구현 완료 후에는 관련 문서와 사용자 매뉴얼에도 같은 변경사항을 반영한다.

## 기준 요구사항

### 목적

여러 코인 거래소의 선물 `funding fee`를 한 화면에서 비교할 수 있는 실시간 대시보드를 제공한다.
참고 이미지와 유사하게 `심볼 x 거래소` 매트릭스 형태의 히트맵 UI를 목표로 한다.

### 기능 요구사항

- 프론트엔드는 `Next.js` 기반으로 구현한다.
- 백엔드는 `Python` 기반으로 구현한다.
- 주요 거래소별 실시간 funding 데이터를 수집해 비교할 수 있어야 한다.
- 화면은 종목을 행으로, 거래소를 열로 가지는 히트맵 테이블 형태여야 한다.
- 현재 funding 값과 거래소가 제공하는 경우 다음 예정 funding 값을 보여줘야 한다.
- 검색, 정렬, 거래소 표시 토글, 즐겨찾기 기능이 필요하다.
- 즐겨찾기는 초기 버전에서 로그인 없이 로컬 저장 방식으로 제공한다.
- 프론트는 백엔드에서 주기적으로 갱신되는 데이터를 실시간에 가깝게 받아와야 한다.

### 초기 범위

- 지원 거래소: `Binance`, `OKX`, `Bybit`, `Bitget`, `KuCoin`, `Gate`
- 저장 방식: 메모리 기반 최신 스냅샷 캐시
- 데이터 제공 방식: `REST snapshot` + `SSE stream`
- 화면 범위: 단일 대시보드 페이지

### 제외 범위

- 사용자 계정 및 서버 저장형 즐겨찾기
- 장기 히스토리 저장과 DB 연동
- 다중 페이지 분석 화면
- 거래 및 주문 기능

## 날짜별 요구사항 변경 이력

### 2026-03-19

- [완료] 1차 버전 기준 요구사항을 정의했다.
- [완료] 10개 주요 티커 중심의 비교형 대시보드로 초기 구현 범위를 제한했다.
- [완료] 현재/예정 funding 전환, 검색, 정렬, 거래소 토글, 즐겨찾기 기능을 포함했다.

### 2026-03-20

- [완료] 거래소별로 제공되는 전체 USDT perpetual 티커로 수집 범위를 확장했다.
- [완료] 종목 수 증가를 고려해 기본 정렬을 `시가총액 내림차순`으로 변경했다.
- [완료] 상단에 거래소 간 funding 괴리(spread)가 가장 큰 5개 종목을 노출하는 요약 기능을 추가했다.
- [완료] 요구사항과 개발 태스크를 날짜별 상태 기반으로 관리하도록 문서를 개편했다.

## 변경 시 작성 템플릿

```md
### YYYY-MM-DD

- [대기] 추가 또는 변경 요구사항
- [작업중] 진행 중 요구사항
- [완료] 반영 완료 요구사항
- [보류] 보류 또는 재검토 요구사항
```
