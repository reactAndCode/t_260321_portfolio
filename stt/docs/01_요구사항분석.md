# 로컬 Whisper STT 프로그램 요구사항 분석

## 1. 문서 개요

본 문서는 로컬 환경에서 Whisper 모델을 사용하여 음성 파일을 텍스트로 변환하는 STT 프로그램의 요구사항을 정리한 문서이다.  
대상 구현체는 Python 기반이며, CLI와 Streamlit 웹 UI를 함께 제공한다.

## 2. 개발 배경

- 외부 API 호출 없이 로컬 PC에서 STT를 수행하고자 함
- Whisper 계열 모델을 활용하여 음성 인식 정확도를 확보하고자 함
- 모델 종류 및 실행 옵션을 코드 수정 없이 설정 파일로 변경 가능해야 함
- 단일 파일뿐 아니라 여러 음성 파일에 대한 일괄 처리도 필요함
- 브라우저에서 파일을 업로드해 전사할 수 있는 UI 요구가 추가됨

## 3. 목표

- 로컬 Whisper 모델 기반 STT 기능 제공
- 설정 파일 기반 모델 경로 및 실행 옵션 관리
- CLI 기반 파일/폴더 전사 처리
- 웹 UI 기반 다중 파일 업로드 전사 처리
- 전사 결과를 `.txt`로 저장하거나 다운로드 가능하게 제공

## 4. 범위

### 포함 범위

- Python CLI 프로그램 구현
- Streamlit 기반 웹 UI 구현
- `faster-whisper` 라이브러리 사용
- 로컬 모델 프로필(`small`, `large`) 지정 및 변경
- YAML 설정 파일 로딩
- 단일 음성 파일 처리
- 폴더 내 다중 음성 파일 배치 처리
- 웹 UI 다중 파일 업로드 처리
- 전사 결과 `.txt` 저장 및 다운로드
- 기본 오류 처리 및 실행 로그 출력

### 제외 범위

- 실시간 스트리밍 음성 인식
- REST API 서버 제공
- 자막 파일(`.srt`) 또는 메타데이터(`.json`) 출력
- 모델 자동 다운로드 기능
- 다중 사용자 인증/권한 관리

## 5. 이해관계자 관점 요구사항

### 사용자 요구사항

- 사용자는 음성 파일 또는 폴더를 입력으로 지정할 수 있어야 한다.
- 사용자는 웹 브라우저에서 음성 파일을 업로드할 수 있어야 한다.
- 사용자는 웹 UI에서 `small`, `large` 모델을 선택할 수 있어야 한다.
- 사용자는 설정 파일에서 모델 경로와 실행 옵션을 변경할 수 있어야 한다.
- 사용자는 전사 완료 후 텍스트 결과를 화면에서 확인하고 파일로 보관할 수 있어야 한다.

### 운영 관점 요구사항

- 외부 네트워크 연결 없이 로컬에서 동작해야 한다.
- 동일한 설정으로 반복 실행 가능해야 한다.
- 일부 파일이 실패하더라도 배치 작업 전체가 즉시 중단되지 않아야 한다.

## 6. 기능 요구사항

### FR-01. 설정 파일 로딩

- 프로그램은 YAML 설정 파일을 읽어 실행 설정을 구성해야 한다.
- 설정 파일에는 최소한 다음 항목이 포함되어야 한다.
  - `models.small`
  - `models.large`
  - `default_model`
  - `device`
  - `compute_type`
  - `language`
  - `beam_size`
  - `output_dir`
  - `supported_extensions`

### FR-02. 로컬 Whisper 모델 사용

- 프로그램은 설정 파일에 지정된 로컬 모델 프로필을 사용하여 Whisper 모델을 로딩해야 한다.
- 웹 UI에서는 사용자가 `small`, `large` 중 하나를 선택할 수 있어야 한다.
- 모델 경로가 존재하지 않으면 명확한 오류 메시지와 함께 실행이 실패해야 한다.

### FR-03. 입력 경로 처리

- CLI 입력값은 단일 파일 또는 폴더를 받을 수 있어야 한다.
- 단일 파일 입력 시 지원 확장자 여부를 검증해야 한다.
- 폴더 입력 시 지정된 확장자 목록에 해당하는 파일만 처리해야 한다.

### FR-04. 웹 업로드 처리

- 웹 UI는 다중 파일 업로드를 지원해야 한다.
- 업로드 파일은 임시 저장 후 전사해야 한다.
- 지원하지 않는 확장자는 선택 또는 실행 단계에서 배제되어야 한다.

### FR-05. 전사 처리

- 각 입력 음성 파일에 대해 Whisper 기반 텍스트 전사를 수행해야 한다.
- 언어는 설정값이 존재하면 고정하고, 없으면 자동 감지해야 한다.
- `beam_size` 등 전사 품질 옵션은 설정 파일에서 제어되어야 한다.

### FR-06. 결과 제공

- CLI 전사 결과는 `.txt` 파일로 저장해야 한다.
- 웹 UI 전사 결과는 화면에 표시해야 한다.
- 웹 UI는 파일별 `.txt` 다운로드를 제공해야 한다.

### FR-07. 배치 처리

- 폴더 입력 시 여러 파일을 순차 처리해야 한다.
- 웹 UI 업로드 시 여러 파일을 순차 처리해야 한다.
- 개별 파일 실패 시 실패 내역을 기록하고 나머지 파일 처리를 계속해야 한다.

### FR-08. 실행 로그 및 오류 메시지

- CLI는 모델 정보, 입력 경로, 출력 경로를 표시해야 한다.
- 파일별 성공 또는 실패 상태를 출력해야 한다.
- 웹 UI는 전체 성공/실패 요약과 파일별 오류를 표시해야 한다.

## 7. 비기능 요구사항

### NFR-01. 사용성

- 명령어 1회 실행만으로 CLI 전사를 수행할 수 있어야 한다.
- 웹 UI는 별도 프론트엔드 빌드 없이 로컬에서 즉시 실행 가능해야 한다.

### NFR-02. 유지보수성

- 설정 로딩, 입력 탐색, 전사, 결과 저장 기능은 모듈 단위로 분리되어야 한다.
- CLI와 웹 UI는 공통 전사 서비스 계층을 공유해야 한다.

### NFR-03. 이식성

- Python 3.10 이상 환경에서 동작해야 한다.
- CPU 환경에서도 실행 가능해야 하며, GPU는 선택 사항이어야 한다.

### NFR-04. 신뢰성

- 잘못된 설정 또는 경로 입력 시 즉시 감지 가능해야 한다.
- 배치 처리 중 일부 실패가 전체 작업의 성공 파일 결과를 훼손하지 않아야 한다.

## 8. 제약사항

- Whisper 모델은 사전에 로컬에 다운로드되어 있어야 한다.
- 다양한 오디오 포맷 지원을 위해 `ffmpeg`가 시스템에 준비되어 있어야 한다.
- 웹 UI는 로컬 단일 사용자 실행을 전제로 한다.
- 출력 형식은 현재 기준 `.txt`만 지원한다.

## 9. 입력/출력 정의

### 입력

- YAML 설정 파일 경로
- CLI용 단일 음성 파일 경로 또는 폴더 경로
- 웹 UI 업로드 파일 목록

### 출력

- CLI용 `.txt` 전사 결과 파일
- 웹 UI 화면 전사 결과
- 웹 UI 파일별 `.txt` 다운로드
- 콘솔 및 웹 요약 로그

## 10. 리스크 및 고려사항

- 모델 크기에 따라 CPU 환경에서 처리 시간이 길어질 수 있음
- `ffmpeg` 미설치 시 일부 포맷 입력에서 실패할 수 있음
- 웹 UI에서 large 모델 선택 시 초기 로딩 시간이 길 수 있음
- 동일한 파일명 처리 시 CLI 출력 파일명이 충돌할 수 있음

## 11. 향후 확장 후보

- `srt`, `json` 출력 추가
- 재귀 폴더 탐색
- ZIP 일괄 다운로드
- 진행률 표시 강화
- 파일명 충돌 방지 정책 추가
- 웹/GUI 외 별도 API 인터페이스 추가
