# 네이버 키워드 분석 웹사이트 요구사항 분석

## 1. 문서 목적
- 본 문서는 `keyword_analysis` 프로젝트의 요구사항을 정리하고, 현재 구현된 MVP의 범위와 향후 확장 방향을 명확히 하기 위한 문서이다.
- 참고 화면은 `plan/img14.png`이며, 해당 이미지처럼 특정 키워드에 대한 분석 결과를 대시보드 형식으로 보여주는 웹사이트를 목표로 한다.

## 2. 프로젝트 개요
- 사용자 입력 키워드를 기준으로 네이버 검색 관련 데이터를 조회한다.
- 핵심 지표를 카드형 대시보드로 표시한다.
- 추이 데이터와 연관 키워드를 함께 제공한다.
- 공식 API 기반 구조를 우선 적용하고, 실데이터 연동이 불가능한 개발 환경에서는 mock 데이터로 대체한다.

## 3. 배경 및 문제 정의
- 사용자는 특정 키워드의 검색 수요와 확장 가능성을 빠르게 파악하고 싶어 한다.
- 참고 이미지 수준의 복잡한 SEO 도구를 한 번에 모두 구현하면 데이터 확보 난이도와 유지 비용이 급격히 올라간다.
- 따라서 1차 버전은 "검색량 확인", "추이 확인", "연관 키워드 탐색", "간단 인사이트 확인"에 집중하는 MVP가 적합하다.

## 4. 이해관계자 관점 요구사항
### 4.1 일반 사용자 요구사항
- 키워드를 입력하고 즉시 결과를 확인하고 싶다.
- 숫자가 한눈에 들어오는 요약 화면이 필요하다.
- 검색량이 어느 정도인지, 최근 추세가 오르는지 내려가는지 알고 싶다.
- 어떤 연관 키워드로 확장할 수 있는지 보고 싶다.

### 4.2 운영자/개발자 요구사항
- 합법적이고 유지 가능한 공식 API 중심 구조가 필요하다.
- API 키가 없는 개발 환경에서도 UI 개발과 데모가 가능해야 한다.
- 프론트와 서버 로직이 분리되어 있어 확장과 유지보수가 쉬워야 한다.
- 향후 DB 저장, 히스토리 관리, 비교 기능을 붙일 수 있어야 한다.

## 5. 기능 요구사항
### 5.1 필수 기능
- 메인 화면에서 키워드를 입력할 수 있어야 한다.
- 입력한 키워드로 분석 API를 호출할 수 있어야 한다.
- 결과 화면에서 다음 항목을 표시해야 한다.
  - 월간 PC 검색량
  - 월간 모바일 검색량
  - 월간 총 검색량
  - 최근 12개월 검색 추이
  - 연관 키워드 목록
  - 자동 생성 인사이트
- 환경변수가 없을 경우 mock 데이터로 동작해야 한다.
- 로딩, 오류, 빈 상태를 사용자에게 구분해서 보여줘야 한다.

### 5.2 선택 기능
- 실데이터 소스 메타 정보 표시
- 연관 키워드 경쟁도 표시
- 초기 예시 키워드 자동 분석

### 5.3 제외 기능
- 회원가입/로그인
- PDF 다운로드
- 보고서 저장
- 다중 키워드 비교
- 콘텐츠 포화도, 문서 발행량, 섹션 분석
- 관리자 페이지

## 6. 비기능 요구사항
### 6.1 사용성
- 사용자는 별도 학습 없이 검색창과 버튼만으로 사용할 수 있어야 한다.
- 결과는 숫자 카드와 표 중심으로 직관적으로 표시되어야 한다.

### 6.2 성능
- 동일 키워드 반복 조회에 대비해 서버 응답 캐싱을 지원해야 한다.
- 초기 렌더링 시 예시 키워드를 자동 로드해 첫 화면이 비어 보이지 않아야 한다.

### 6.3 유지보수성
- 데이터 수집 로직은 `lib`에 분리한다.
- UI와 데이터 로직은 느슨하게 결합되어야 한다.
- 타입 정의는 공용으로 사용 가능해야 한다.

### 6.4 보안
- 외부 API 키는 환경변수로 관리해야 한다.
- 클라이언트에서 API 키를 직접 노출하면 안 된다.

## 7. 데이터 요구사항
### 7.1 입력 데이터
- 사용자 입력 키워드 문자열

### 7.2 출력 데이터
- 키워드 원문
- 검색량 요약 정보
- 월별 추이 배열
- 연관 키워드 배열
- 인사이트 배열
- 데이터 출처 메타 정보

### 7.3 외부 연동 데이터
- 네이버 SearchAd API
  - 키워드 검색량
  - 연관 키워드
  - 경쟁도
- 네이버 DataLab API
  - 월별 검색 추이

## 8. 사용자 시나리오
### 시나리오 1: 일반 분석
1. 사용자가 메인 화면에 접속한다.
2. 예시 키워드 분석 결과가 기본 표시된다.
3. 사용자가 다른 키워드를 입력하고 `분석 시작` 버튼을 누른다.
4. 시스템은 서버 API를 통해 데이터를 조회한다.
5. 검색량 카드, 추이 차트, 연관 키워드, 인사이트를 갱신한다.

### 시나리오 2: API 키 미설정 개발 환경
1. 개발자가 환경변수 없이 앱을 실행한다.
2. 시스템은 실데이터 호출 대신 mock 데이터를 제공한다.
3. UI 개발과 테스트가 가능하다.

### 시나리오 3: 외부 API 오류
1. 사용자가 키워드를 검색한다.
2. 외부 API가 실패하거나 응답이 비정상이다.
3. 시스템은 오류 메시지를 반환한다.
4. 화면에는 오류 상태가 표시된다.

## 9. 성공 기준
- 사용자가 임의의 키워드를 입력해 결과를 확인할 수 있다.
- 실데이터 또는 mock 데이터 중 하나로 항상 대시보드가 동작한다.
- 핵심 분석 요소 4종 이상이 한 화면에서 제공된다.
- 모바일과 데스크톱에서 레이아웃이 깨지지 않는다.
- 서버 API, 타입체크, 빌드가 정상 동작한다.

## 10. 제약사항 및 가정
- 공식 API만으로 참고 이미지의 모든 지표를 완전 재현할 수는 없다.
- SearchAd와 DataLab API는 각각 별도 인증 정보가 필요하다.
- 일부 데이터가 없으면 `-` 또는 빈 상태로 표시한다.
- 본 프로젝트의 1차 목적은 "빠르게 확인 가능한 분석형 MVP"이며, 고급 SEO 도구 전체 구현이 아니다.

## 11. 향후 확장 요구사항
- 검색 이력 저장
- 여러 키워드 비교
- 날짜 범위 선택
- 차트 고도화
- CSV/PDF 내보내기
- 콘텐츠 포화도나 문서 발행량 같은 추가 지표 도입
