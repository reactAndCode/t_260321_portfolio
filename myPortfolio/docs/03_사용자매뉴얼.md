# 03. 사용자 매뉴얼

## 1. 문서 목적

이 문서는 포트폴리오 사이트를 운영하거나 수정하는 사용자를 위한 안내서다.  
콘텐츠 수정 위치, 폴더 구조, 파일 역할, GitHub Pages 배포 방법을 포함한다.

## 2. 폴더 구조

```text
myPortfolio/
├─ index.html
├─ 404.html
├─ README.md
├─ about/
│  └─ index.html
├─ contact/
│  └─ index.html
├─ projects/
│  └─ index.html
├─ services/
│  └─ index.html
├─ assets/
│  ├─ css/
│  │  └─ styles.css
│  ├─ js/
│  │  ├─ app.js
│  │  └─ site-data.js
│  ├─ favicon.svg
│  └─ og-cover.svg
└─ docs/
   ├─ README.md
   ├─ 01_요구사항분석.md
   ├─ 02_구현설계서_task.md
   └─ 03_사용자매뉴얼.md
```

## 3. 파일 설명

### 루트 파일

- `index.html`
  - 메인 홈 페이지 진입 파일
- `404.html`
  - 존재하지 않는 경로 접근 시 표시되는 에러 페이지
- `README.md`
  - 프로젝트 개요와 배포 안내 문서

### 페이지 폴더

- `about/index.html`
  - 소개 페이지 진입 파일
- `contact/index.html`
  - 문의 페이지 진입 파일
- `projects/index.html`
  - 프로젝트 목록 페이지 진입 파일
- `services/index.html`
  - 서비스 소개 페이지 진입 파일

### assets 폴더

- `assets/css/styles.css`
  - 전체 디자인, 레이아웃, 반응형, 애니메이션 스타일을 관리
- `assets/js/site-data.js`
  - 이름, 소개, 서비스, 프로젝트, 문의 정보 등 실제 콘텐츠 데이터를 관리
- `assets/js/app.js`
  - 헤더/푸터/페이지 내용 렌더링, 언어 전환, 스크롤 애니메이션을 처리
- `assets/favicon.svg`
  - 브라우저 탭 아이콘
- `assets/og-cover.svg`
  - 소셜 미리보기용 Open Graph 이미지

### docs 폴더

- 분석서, 설계서, 매뉴얼 등 프로젝트 문서 저장 폴더

## 4. 가장 자주 수정하는 파일

실제 운영 시 가장 먼저 수정해야 하는 파일은 `assets/js/site-data.js`다.

여기서 수정 가능한 대표 항목은 다음과 같다.

- 브랜드명
- 역할 소개 문구
- 이메일 주소
- GitHub 주소
- 홈 화면 문구
- 서비스 목록
- 프로젝트 목록
- 소개 섹션 내용
- 문의 안내 문구

## 5. 콘텐츠 수정 방법

### 브랜드 정보 수정

`assets/js/site-data.js`의 `profile` 영역을 수정한다.

- `name`: 사이트 이름
- `role`: 역할/소개 문구
- `email`: 이메일 주소
- `github`: GitHub 주소
- `location`: 활동 지역

### 서비스 내용 수정

`services.items` 배열을 수정한다.

각 항목에는 다음 정보가 들어간다.

- 제목
- 메타 설명
- 본문 설명
- 태그 목록

### 프로젝트 내용 수정

`projects.items` 배열을 수정한다.

각 항목에는 다음 정보가 들어간다.

- 제목
- 역할
- 결과
- 설명
- 기술 스택

### 다국어 수정

문자열은 대부분 아래와 같은 구조를 사용한다.

```js
title: {
  ko: "한국어 문구",
  en: "English copy"
}
```

한국어와 영어를 모두 수정해야 언어 전환 시 자연스럽게 표시된다.

## 6. 디자인 수정 방법

디자인은 `assets/css/styles.css`에서 수정한다.

주요 수정 지점:

- 색상: `:root` 변수
- 폰트와 타이포 크기: `body`, `.hero h1`, `.page-title h1`
- 카드 스타일: `.card`, `.service-card`, `.project-card`
- 레이아웃: `.hero__grid`, `.project-grid`, `.service-grid`
- 반응형: `@media` 구간

## 7. 동작 방식 이해

### 페이지 표시 방식

- 각 HTML 파일에는 공통적으로 `#app`만 있다.
- 실제 페이지 내용은 `assets/js/app.js`가 동적으로 그린다.
- 현재 페이지는 `body`의 `data-page` 값으로 구분한다.

### 언어 전환 방식

- 사용자가 `KR`, `EN` 버튼을 누르면 언어 상태가 변경된다.
- 선택한 언어는 브라우저 `localStorage`에 저장된다.
- 이후 다시 접속해도 마지막 언어가 유지된다.

## 8. GitHub Pages 배포 방법

1. 모든 파일을 GitHub 저장소에 push 한다.
2. GitHub 저장소의 `Settings > Pages`로 이동한다.
3. `Deploy from a branch`를 선택한다.
4. 브랜치는 `main`, 폴더는 `/ (root)`를 선택한다.
5. 저장 후 배포 URL이 생성되면 사이트를 확인한다.

## 9. 운영 시 주의사항

- 연락처와 GitHub 링크는 반드시 실제 값으로 교체해야 한다.
- 현재 프로젝트와 서비스 내용은 예시 성격이므로 실제 포트폴리오 내용으로 교체하는 것이 좋다.
- Open Graph 이미지는 공유 시 미리보기 품질에 영향을 주므로 실제 브랜드 이미지로 교체하는 것이 좋다.
- GitHub Pages는 정적 호스팅이므로 자체 문의 전송 기능은 없다.

## 10. 추천 운영 순서

1. `site-data.js`에서 본인 정보와 작업물 내용을 교체한다.
2. `styles.css`에서 색상과 톤을 본인 브랜딩에 맞게 조정한다.
3. GitHub Pages에 배포한다.
4. 실제 URL로 모바일/데스크톱 화면을 다시 확인한다.
5. 링크, 이메일, 언어 전환이 모두 정상 동작하는지 점검한다.
