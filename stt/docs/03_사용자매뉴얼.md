# 로컬 Whisper STT 프로그램 사용자 매뉴얼

## 1. 개요

이 프로그램은 로컬에 저장된 Whisper 모델을 사용하여 음성 파일을 텍스트로 변환하는 Python 기반 도구이다.  
CLI와 Streamlit 웹 UI를 함께 제공하며, 인터넷 API 호출 없이 로컬 환경에서 STT를 수행할 수 있다.

## 2. 사전 준비

### 2.1 필수 조건

- Python 3.10 이상 설치
- 로컬 Whisper 모델 다운로드 완료
- `ffmpeg` 설치 및 환경 변수 등록

### 2.2 권장 환경

- 일반 PC: `device: cpu`, `compute_type: int8`
- GPU 사용 가능 환경: `device: cuda`

## 3. 설치 방법

프로젝트 루트에서 가상환경을 만들고 패키지를 설치한다.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -e .
```

테스트까지 사용하려면:

```bash
pip install -e .[dev]
```

## 4. 설정 파일 작성

`config.example.yaml`을 참고하여 `config.yaml`을 작성한다.

예시:

```yaml
models:
  small: "D:/models/faster-whisper-small"
  large: "D:/models/faster-whisper-large-v3"
default_model: "small"
device: "cpu"
compute_type: "int8"
language: null
beam_size: 5
output_dir: "outputs"
supported_extensions:
  - ".mp3"
  - ".wav"
  - ".m4a"
  - ".flac"
  - ".ogg"
```

### 주요 항목 설명

- `models.small`, `models.large`
  - 로컬 Whisper 모델 폴더 경로
- `default_model`
  - CLI 기본 모델 프로필
- `device`
  - 연산 장치, 일반적으로 `cpu` 또는 `cuda`
- `compute_type`
  - 연산 타입, CPU에서는 보통 `int8`
- `language`
  - `null`이면 자동 감지
- `output_dir`
  - CLI 결과 텍스트 파일 저장 경로

## 5. CLI 실행 방법

### 5.1 단일 파일 전사

```bash
stt-cli --config config.yaml --input .\sample.wav
```

### 5.2 폴더 일괄 전사

```bash
stt-cli --config config.yaml --input .\audio
```

### 5.3 모델 프로필 선택

```bash
stt-cli --config config.yaml --input .\audio --model small
```

### 5.4 모듈 방식 실행

```bash
$env:PYTHONPATH="src"
python -m stt_cli --config config.yaml --input .\sample.wav --model large
```

## 6. 웹 UI 실행 방법

브라우저 업로드 방식으로 사용하려면 다음 명령을 실행한다.

```bash
streamlit run src/stt_cli/web_app.py -- --config config.yaml
```

웹 UI에서 가능한 작업:

- 다중 음성 파일 업로드
- `small`, `large` 모델 선택
- 전사 결과 화면 확인
- 파일별 `.txt` 다운로드

## 7. 실행 결과 확인

CLI 실행 시 콘솔에 다음 정보가 출력된다.

- 모델 프로필
- 모델 경로
- 입력 경로
- 출력 폴더
- 파일별 처리 성공/실패
- 전체 처리 요약

예시:

```text
Model profile: small
Model path: D:\models\faster-whisper-small
Input path: .\audio
Output dir: outputs
[OK] audio\a.wav -> outputs\a.txt
[FAIL] audio\b.wav: <error message>
Completed. total=2 success=1 failed=1
```

웹 UI에서는 다음 형태로 결과를 확인한다.

- 업로드 파일 수 표시
- 전사 성공/실패 요약
- 파일별 전사 텍스트 표시
- 파일별 다운로드 버튼 표시

## 8. 결과 파일 위치

- CLI 결과는 `output_dir`에 저장된다.
- 웹 UI 결과는 기본적으로 화면 표시와 다운로드 중심이며, 업로드 원본은 임시 디렉터리에서 처리된다.

## 9. 자주 발생하는 문제와 해결 방법

### 9.1 모델 경로 오류

- 증상: 실행 시작 시 모델 경로 관련 오류 발생
- 조치: `config.yaml`의 `models.small`, `models.large` 경로 확인

### 9.2 입력 파일 경로 오류

- 증상: `Input path not found` 오류 발생
- 조치: `--input`에 전달한 파일 또는 폴더 경로 확인

### 9.3 지원하지 않는 확장자

- 증상: 특정 파일이 처리되지 않음
- 조치: `supported_extensions`에 포함되어 있는지 확인

### 9.4 ffmpeg 미설치

- 증상: 일부 오디오 파일에서 디코딩 실패
- 조치: `ffmpeg` 설치 후 시스템 `PATH`에 등록

### 9.5 속도가 느린 경우

- 증상: CPU 환경에서 처리 시간이 길게 소요됨
- 조치: 더 작은 모델 사용, `compute_type` 조정, 가능하면 GPU 사용
