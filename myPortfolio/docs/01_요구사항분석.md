# 01. 요구사항 분석

## 1. 프로젝트 개요

- 프로젝트명: GitHub Pages 기반 개발자 포트폴리오 사이트
- 목적: 프리랜스/외주 문의를 유도할 수 있는 개발자 포트폴리오 웹사이트 구축
- 배포 환경: GitHub Pages
- 구현 방식: 정적 HTML/CSS/JavaScript
- 언어 범위: 한국어/영어 2개 국어

## 2. 요구사항 배경

사용자는 GitHub Pages로 배포 가능한 개발자 포트폴리오 사이트를 만들고자 했다.  
단순한 이력 소개형 사이트가 아니라, 외주/프리랜스 고객이 사이트를 보고 바로 문의하고 싶어지는 구조가 필요했다.  
초기에는 실제 프로젝트 자료와 소개 문구가 충분하지 않은 상태를 전제로 하므로, 더미 콘텐츠로 먼저 완성하고 나중에 실제 콘텐츠만 교체할 수 있는 구조가 중요했다.

## 3. 핵심 요구사항

### 3.1 목표 요구사항

- 프리랜스/외주 수주에 적합한 포트폴리오 사이트여야 한다.
- 첫 화면에서 자기소개보다 제공 가능한 서비스와 전문 분야가 먼저 드러나야 한다.
- 시각적으로 평범한 템플릿이 아니라 실험적이고 인상적인 분위기를 가져야 한다.
- GitHub Pages에서 바로 배포 가능해야 한다.

### 3.2 콘텐츠 요구사항

- 실제 콘텐츠가 부족한 상태에서도 사이트 골격을 먼저 완성할 수 있어야 한다.
- 프로젝트, 서비스, 소개, 문의 콘텐츠를 데이터 교체 방식으로 쉽게 수정할 수 있어야 한다.
- 한국어/영어를 전환할 수 있어야 한다.
- 문의는 이메일과 GitHub 링크 중심으로 유도해야 한다.

### 3.3 구조 요구사항

- 단일 페이지가 아니라 멀티페이지 브랜딩 사이트로 구성해야 한다.
- 최소 페이지 범위는 홈, 프로젝트, 서비스, 소개, 문의 페이지를 포함해야 한다.
- GitHub Pages의 정적 호스팅 특성에 맞는 상대 경로 구조를 사용해야 한다.
- 404 페이지를 제공해야 한다.

## 4. 사용자 관점 분석

### 4.1 주요 사용자

- 개발 외주를 맡기려는 개인 창업자
- 소규모 팀 또는 브랜드 운영자
- 기존 서비스의 랜딩/프론트엔드 개선이 필요한 고객

### 4.2 사용자 기대 행동

- 첫 화면에서 어떤 문제를 해결해줄 수 있는지 빠르게 이해한다.
- 프로젝트와 서비스 내용을 보고 신뢰도를 판단한다.
- 연락 수단을 확인한 뒤 이메일 또는 GitHub를 통해 문의한다.

## 5. 기능 요구사항

- 공통 헤더와 네비게이션 제공
- 페이지별 콘텐츠 렌더링
- 언어 토글 기능 제공
- 선택 언어를 브라우저에 저장
- 스크롤 진입 애니메이션 제공
- 연락 링크 클릭 가능
- 없는 경로 접근 시 404 화면 제공

## 6. 비기능 요구사항

- 빌드 도구 없이 정적 파일만으로 동작해야 한다.
- 모바일과 데스크톱에서 모두 대응해야 한다.
- 수정 포인트가 명확해야 하며, 비개발자도 텍스트 교체 위치를 찾기 쉬워야 한다.
- GitHub Pages 사용자 페이지와 프로젝트 페이지 모두를 고려한 경로 설계가 필요하다.

## 7. 요구사항 해석 결과

- 구현 복잡도보다 배포 단순성과 유지보수성을 우선한다.
- 콘텐츠 부족 문제를 해결하기 위해 UI와 데이터 구조를 분리한다.
- 다국어는 라이브러리 없이 데이터 객체 기반으로 관리한다.
- 문의 기능은 백엔드 없는 정적 사이트 제약에 맞춰 링크형으로 설계한다.
- 사이트의 핵심 메시지는 “무엇을 할 수 있는가”와 “함께 일하면 어떤 결과가 나오는가”에 맞춘다.
